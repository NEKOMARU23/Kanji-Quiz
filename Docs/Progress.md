## 2. スケジュール（案）

残り約14週。1モードあたり2〜3週間のペースで進める。

| 時期 | やること | 状況 |
|---|---|---|
| 10月 | 設計、共通の土台、書き順クイズ | 完了（ビルド確認を除く） |
| 10月下旬 | 書き順クイズの仕上げ、全モード共通の部品（ひな形、モードの定義、中断メニュー、キーボード操作） | 完了 |
| 11月上旬〜中旬 | 本物の漢字さがし | 遊べる（2026-10-27。意味と例文を除く） |
| 11月下旬 | タイトル・モード選択画面、四字熟語づくり | 完成（タイトル・モード選択・設定・漢字帳・クレジットは 2026-10-31、四字熟語づくりは 2026-11-04 の PR #18） |
| 11月下旬〜12月 | 読み当て（2026-11-07 に完了）、使い分け（フェーズ1の残り）。余裕があれば文章クイズ、画像で名前当て | 読み当ては完了。使い分けは実装まで完了（2026-11-14）、人の確認とビルド確認が残り |
| 1月 | 仕上げ、ビルド確認、ポートフォリオ資料 | 未着手 |

- 2026-10-27：返信文クイズは、正しい返信文を作る力がまだ足りない（開発者も AI も）ため後回しにし、データを用意しやすいモードから作ることにした。
- 2026-11-07：プレイヤーが問題を作る機能（問題作成モード）と、オンライン共有は作らないことにした。理由は、画像や文章を自由に持ち込むと不適切な内容や著作権の問題が避けにくく、公開の場を運営する責任が残るため。1人の開発では負えないと判断した。
- 2026-11-07：フェーズ1は5モード（書き順クイズ・本物の漢字さがし・四字熟語づくり・読み当て・使い分け）にする。返信文クイズは「文章クイズ」として、画像で名前当てと合わせて余裕があれば作る。
- 2026-10-27：人名用漢字は数がとても多く（異体字を含めると膨大）、ほかのモードに混ぜると何でもありになるというアドバイスを受けた。どの難易度も常用漢字だけにし、人名用漢字は別のモード（人名漢字のモード、内容は未定）で扱うことにした。

- エディタで Play すると TMP フォントアセット（`KleeOne-Regular SDF.asset`）に差分が出る。コミット前に消す。
- シーン `StrokeOrder` と `RealKanji` の難易度は Easy で保存する。テストでは F1 の切り替えボタンを使う。
- 本物の漢字さがしの仕様は PR #9 で決めた（GameSpec.md 2.1）。偽物と熟語のデータは PR #10、ゲーム・重なりの不具合の修正・出題範囲の見直しは PR #11（2026-10-27 マージ済み）。
- 次の作業は、最新の main から新しいブランチを切って始める（例：`git checkout -b feature/kono/<内容> origin/main`。作業ツリーが変わらない形で切ると、Unity の「シーンが外で変更された」ダイアログが出にくい）。
- 漢字セットの名前は 2026-10-27 に変えた：`Elementary`（簡単）・`JoyoCommon`（常識）・`JoyoRare`（困難）・`Hyogai`（どの難易度にも使わない。人名漢字のモード用）。以前の `Joyo` はもうない。
- データを作り直す順番：①`Tools/generate_kanji_sets.py`（漢字セット）→ ②`Tools/generate_kanji_words.py`（熟語）→ ③`Tools/generate_real_kanji_fakes.py`（偽物）。②と③は①の漢字セットを読む。元データ（KANJIDIC2・JMdict・BabelStone IDS）はリポジトリに入れていないので、使い方はスクリプトの先頭を見てダウンロードする。
- 偽物の見た目の確かめ方（BugFixes.md 1.4）：部首を黒、借りた部品を青で、本物1字と偽物7つを1行に描いた画像を、部首ごとに作って見る。そのスクリプトはリポジトリに入れていない（必要になったら `Tools/` に作る）。
- Play で確かめたあとは、`BestRecord_<モード>_<難易度>` と `WeakQuestions_<モード>_<難易度>`（モードは StrokeOrder・RealKanji、難易度は Easy・Normal・Hard）を `PlayerPrefs.DeleteKey` で消す。漢字帳（`KanjiBook_<モード>`）と表示の設定（`Option_Hiragana`）も同じ。ユーザーが自分で遊んだ記録が残っていることもあるので、確認用に入れたもの以外は聞いてから消す。設定の「記録を消す」は、ユーザーの記録も消えるので Play では押さない。
- モード選択の見た目の案（モックアップ）は claude.ai のアーティファクト「モード選択画面のレイアウト案」にある（採用したのは時間割表 F1 と黒板 ②-F 改 a）。
- テスト用の難易度切り替え（F1、`DebugDifficultySwitcher`）は、モード選択ができたあとも残すことにした（2026-10-30）。
- 意味と例文のデータ（`Data/KanjiMeanings/`）は AI で作った。直すときは JSON を手で直し、`python -I Tools/check_kanji_meanings.py` で確かめる（出題する字がそろっているか、読みのつけ忘れ、難易度より上の漢字、長さ）。意味の正しさや読みの正しさはスクリプトでは確かめられないので、確認用の一覧（claude.ai のアーティファクト「意味と例文の確認」）で見る。
- 表示の設定は PlayerPrefs の `Option_Hiragana`。Play で確かめたあとは消す。
