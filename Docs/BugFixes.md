## 1. 本物の漢字さがしで、偽物の漢字の部首と部品が重なる（2026-10-27）

### 1.1 症状

本物の漢字さがし（GameSpec.md 2.1）の偽物の中に、部首と、別の漢字から借りてきた部品が重なって、字としておかしく見えるものがあった。

- 例：「楯」の偽物「木＋頃」で、頃の左側が木へんの右はらいに重なる。「錬」の偽物「金＋師」で、師が金へんの右側に食い込む。
- 木へん・くさかんむり・いとへん・かねへん・てへん・ごんべん・しんにょうなど、よく使われる部首で多かった。

### 1.2 偽物の作り方（前提）

- 漢字の書き順データ（KanjiVG の SVG）は、1画ごとの線のデータが「部首」「残りの部分」のような部品のグループに分かれている。
- 偽物は「本物の部首の線」＋「別の漢字から借りた部品の線」で組み立てる。
- 借りた部品は、本物の**部首以外の部分の外枠（その部分の線をすべて囲む長方形）**に合わせて、縦横に縮める・伸ばす。

### 1.3 原因

3つの原因が重なっていた。

1. **外枠が部首の線の上まで広がっていた（主な原因）**
   - 本物の部首以外の部分は、部首をよけるような形をしていることが多い。例えば「楯」の「盾」は、左はらいが木へんの下まで長く伸びている。そのため、外枠は部首の線と重なる場所まで広がる。
   - 本物は、外枠の中で部首のある場所を空けているので重ならない。借りた部品はそうなっていないので、外枠いっぱいに広げると部首とぶつかる。
   - 外枠という長方形だけで「置いてよい場所」を表していたことが、根本の問題だった。
2. **重なりの判定の基準が、本物の重なり具合だった（調べる途中で見つけた）**
   - 本物の部品も、もともと部首に重なっている字がある（「省」の「少」の払いが目を横切る、「夏」の「夂」、「牽」など）。
   - 最初の修正では「本物と同じくらいの重なりなら許す」としたため、偽物の部品が部首の**別の場所**にぶつかっても通っていた。
3. **部品を置く場所が小さすぎる字があった（調べる途中で見つけた）**
   - 「太」（大の中の点）、「永」の点、「系」の上の1画などは、部首以外の部分がとても小さい。借りた部品がつぶれて読めなかった。
   - 「加」の「口」のような小さな場所に、「寺」「車」のような画数の多い部品を入れると、線が詰まって読めなかった。

### 1.4 調べ方

目で見て探すと見落としが出るので、**重なりを数値にしてから、画像で確かめた**。

1. **重なりを数値にする**
   - 偽物をゲームと同じ方法で組み立てる Python を書いた。
   - 部首の線と借りた部品の線を、それぞれ太さつきで白黒の画像に描き（Pillow）、両方が塗られている面積を数えた（numpy）。
   - 偽物の候補 28,966 個のうち、本物より重なりが 20 以上多いもの（面積の単位は KanjiVG の座標で 1×1）が 6,865 個あった。部首ごとに数え、多いもの（木へん 365 個、くさかんむり 350 個など）から調べた。
2. **画像で確かめる**
   - 部首を黒、借りた部品を青で描いた一覧の画像を作った。
   - 重なりが大きいものを部首ごとに並べ、原因が「外枠が部首の上まで広がっている」ことだとわかった。
3. **修正したあと、部首を1つずつ確かめる**
   - 位置ごとの部首（全 266 種類）について、本物1字と偽物7つを描いた画像を 23 枚作り、すべて見た。
   - このときに、原因 2（省・夏など）と原因 3（太・加など）を見つけた。

### 1.5 直し方

偽物を作る Python（`Tools/generate_real_kanji_fakes.py`）で、**部品を置く枠を探してから JSON に書く**ようにした。ゲームは、その枠に部品を合わせるだけにした。

1. **部首の側から枠を狭める（原因 1）**
   - 本物の部首以外の部分の外枠から始め、部首のある側の辺を少しずつ内側へ動かす（1回 4%、最大 32%）。
   - 狭める辺は部首の位置で決める（へんなら左、しんにょうなら左と下、かまえなら4辺）。
   - 狭めるたびに部品を組み立て直して重なりを調べ、重ならなくなった枠を使う。どこまで狭めても重なる候補や、狭めて縦横比が崩れる候補は使わない。
2. **本物が触れている部首の線は、比べる対象から外す（原因 2）**
   - 「部首の線の画像」から「本物の部品の線の画像」を引いたもの（本物が触れていない部首の線）と、借りた部品の線との重なりを調べるようにした。
   - こうすると、省の「少」のように本物がもともと重なっている場所には部品が来てもよく、それ以外の場所にぶつかる偽物は使わなくなる。
3. **小さすぎる場所と、詰めすぎる部品を除く（原因 3）**
   - 部首以外の部分の幅か高さが 20 未満（字の約5分の1）の漢字は出題しない。
   - 枠の面積に対して画数が多すぎる部品（1画あたり 250 未満）は使わない。
4. **ゲーム側（C#）の変更**
   - 問題データ（JSON）の偽物ごとに、部品を置く枠 `box` を足した。
   - `FakeKanjiComposer` は、`box` があればそこに、なければ今までどおり外枠に部品を合わせる。
   - 枠の座標を変換するテストを足した（KanjiVG の座標は y が下向き、ゲームは y が上向きで中心が原点）。

**設計上の判断**

- **重い判定は Python で事前に済ませる**：線を画像に描いて重なりを数えるのは重いので、ゲーム中には行わない。JSON を作るときに一度だけ行い、結果（枠）だけを JSON に入れる。
- **枠を JSON に入れる**：ゲーム側で同じ計算をし直すと、Python と C# でわずかに結果が違って重なりが戻るおそれがある。Python が確かめた枠をそのまま使えば、確かめたとおりの字がゲームに出る。

### 1.6 結果

- 部首ごとの一覧の画像（全 266 種類）で、偽物の部品が部首から離れたことを確かめた。木へん・かねへん・しんにょう・くさかんむりなども、重なりがなくなった。
- 出題できる漢字（修正前 → 修正後）：小学 749 → 737、常用 993 → 993、常用外 687 → 685（合わせて 2,429 → 2,415）。減った 14 字は、部首以外の部分が小さすぎる字（太・永など 5 字）と、条件を満たす偽物が3つ作れなくなった字（鳴など 9 字）。
  - この数字は、修正した時点の出題範囲（常識＝小学校で学ばない常用漢字すべて、困難＝常用漢字以外）でのもの。同じ日に出題範囲を常用漢字だけに変えた（GameSpec.md 5.2）。
- ゲームで Play して、偽物（しんにょうの「逷」「逧」など）が部首と重ならずに描かれることを確かめた。
- 代わりに、JSON を作るスクリプトの実行時間が約1分から約9分に延びた。ゲームを遊ぶときの読み込みは変わらない。
- テスト：枠に合わせて組み立てるテストと、座標の変換のテストを足した。

### 1.7 学んだこと

- **「形」を長方形で代わりに表すと、形のくぼみが失われる**。外枠は手軽だが、部首をよけるような形の部品には合わなかった。実際に線を描いて重なりを数える方法に変えて解決した。
- **基準を「本物と比べて」にするときは、何と比べるかに注意する**。本物にもともとある重なりを丸ごと許すと、別の場所の重なりも見逃した。「本物が触れていない場所」と比べることで、正しく判定できた。
- **数値で絞り込んでから、目で全部確かめる**。数値だけでは「小さすぎて読めない」ような問題は見つからなかった。部首ごとに画像を並べて全部見たことで、別の原因を2つ見つけられた。
