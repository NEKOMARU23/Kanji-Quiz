## 1. ゲーム概要

漢字をテーマにした**複数のクイズモード**で遊べるゲーム。
プレイヤーが問題を作る機能や、オンラインで問題を共有する機能は作らない（2026-11-07 に決定。2.3・2.4）。

- ジャンル：教育・学習クイズ
- 想定プレイヤー：漢字を学習・確認したい人、問題を作って共有したい人
- 対象年齢：全年齢。子ども向けに限定はしないが、子どもも遊べるようにする

### 1.1 ねらい

- 漢字の形・読み・使い分け・熟語を、いろいろな形式のクイズで遊びながら学ぶ。
- 作品の範囲は、開発者が作るモードに限る。プレイヤーが問題を作る機能や、オンラインで問題を共有する機能は作らない（2026-11-07 に決定）。
  - 理由：画像や文章を自由に持ち込めると、不適切な内容や著作権の問題が避けにくい。そうなると、公開の場を運営する責任が開発者に残る。1人の開発では、その責任と作業量を負えない。
- 問題はJSON（データ）として読んでいるので、モードや問題は開発者がデータを足すだけで増やせる。

## 2. 全体構成（構想）

> この章は今後の構想です。詳細は「8.3 決めること」で詰めます。

### 2.1 ゲームモード（構想）

書き順クイズ以外のモードの概要。詳細は各モードの実装前に詰める（本物の漢字さがしと四字熟語づくりは決めて実装した）。

**本物の漢字さがし**

2026-10-27 に仕様を決め、実装した（シーンは `RealKanji.unity`）。

*遊び方*

- 問題文は「本物の漢字はどれ？」だけ。実在する漢字1つと偽物3つの**4択**を **2×2** に大きく並べる。
- 4つとも、漢字の下に**読み**を出す（プレイ中から表示する）。
  - 本物：音読みを1つ（カタカナ）。音読みのない漢字（畑など）は訓読み（ひらがな）。
  - 偽物：借りてきた部品の音読み。漢字は音を表す部品で読みが決まることが多い（清・晴・精＝セイ）ので、それらしく見える。例：「氵＋寺」→「ジ」。
- 難易度は書き順クイズと同じく**出題範囲**で変える（簡単＝小学漢字、常識＝小学校で学ばない常用漢字のうちよく使う半分、困難＝あまり使わない半分。5.2）。人名用漢字は入れない。
- 問題数（5・7・7問）、級、自己ベスト、苦手な漢字の復習、制限時間なしは、書き順クイズと同じ（3.6〜3.8）。苦手な漢字は本物の漢字で覚える。
  - 保存のキーは `BestRecord_RealKanji_<難易度>` と `WeakQuestions_RealKanji_<難易度>`。正解した字は漢字帳（`KanjiBook_RealKanji`）に集める。
- 振り返りでは、問題文の代わりに本物の読み・使用例・意味・例文を3行で出す（1行目に読みと使用例、2行目に意味、3行目に例文。例文の中の本物の字は朱色）。
  - 例：「本物は「海」（カイ）　使用例：海外（かいがい）、北海道（ほっかいどう）、海上（かいじょう）／意味：地球の上に広がる、しおからい水のあつまり。／例文：夏休みに家族で海へ泳ぎに行った。」
  - 各選択肢の字の右に説明を出す。本物は「本物」、偽物はどの部品の組み合わせか（例：「氵＋舎（捨の右側）」。漢字1字をまるごと借りたときは「氵＋寺」）。
  - 使用例は熟語を3つまで。熟語は JMdict（EDRDG、CC BY-SA 4.0）から自動で取る（下の「使用例の熟語のデータ」）。
  - 意味と例文は AI（Claude）で作ったデータ（下の「意味と例文のデータ」）。KANJIDIC2 には英語の意味しかないため。
  - 中断メニューで「出題の字のほかは ひらがなで表示」を ON にすると、意味と例文の漢字を、本物の字のほかはひらがなで出す（まだ漢字を習っていない子ども向け。4.4）。
- 正解の位置は問題を作るときにランダムに決める。選び方とキー操作（1〜4、Enter など）は書き順クイズと同じ（4.5）。

*偽物の作り方*

- 本物と**同じ部首**を同じ位置に残し、**部首以外の部分**を別の漢字から借りてきたものに入れ替える。
  - 部首は KanjiVG の `kvg:radical="general"` が付いた部品（なければ `"tradit"`、康熙字典の部首。頭の「頁」など）。位置は `kvg:position`（left・right・top・bottom・kamae・tare・nyo）。書き順の都合で2つに分かれた部首（国の「囗」など）も使う。
  - 入れ替える部品は、**その難易度と、それより下の難易度の出題範囲**にある漢字に限る（簡単なら小学漢字だけ、困難なら全範囲）。見慣れた部品だけで偽物を作り、読みも自然にするため。借り方は2通り：
    - ほかの漢字の同じ場所にある部品（例：持の右側の「寺」）。元の場所の形に近いので、縮めても崩れにくい。こちらを優先する
    - 漢字1字をまるごと（例：「寺」）。ほかの漢字で部品として使われている漢字だけにする。偏・旁・繞・垂れ・構えの部首を持つ漢字（活など）は、部首が2つあるように見えるので丸ごとは借りない
  - 本物の部首と同じ部品を含む漢字からは借りない（艹＋苗のように部首が重なるため）。
  - 借りた部品は、**部品を置く枠**に合わせて縮める・伸ばす。囲い（kamae）・垂れ（tare）・繞（nyo）も同じやり方で作る。
    - 枠は元の部分の外枠（bounding box）から始める。外枠は部首の線と重なる場所まで広がっていることがある（楯の「盾」の左はらいが木へんの下まで伸びているなど）ので、部首の側から少しずつ狭め（1回 4%、最大 32%）、借りた部品の線が部首の線にほぼ重ならない枠を探す（2026-10-27）。
    - 重なりは、線を太さつきで描いて調べる。本物の部品も部首に重なっている字（省の「少」、夏の「夂」など）があるので、本物の部品が触れている部首の線は除いて比べる。重なりの面積が KanjiVG の座標で 8 以下なら重なっていないとする。
    - どこまで狭めても重なる候補は使わない。狭める辺は部首の位置で決める（left なら左の辺、nyo なら左と下、kamae なら4辺）。
  - 字形が崩れるものは使わない：
    - 借りた部品と枠の縦横比が 1.5 倍以上違うもの
    - 借りた部品の画数が元の部分より多すぎるもの（2倍か +4 画を超える）
    - 枠の面積に対して画数が多すぎるもの（1画あたり KanjiVG の座標で 250 未満。加の「口」くらいの枠（32×43）なら5画まで）
  - 部首以外の部分が小さすぎる漢字（幅か高さが KanjiVG の座標で 20 未満。太・永の点、系の上の1画など）は出題しない。借りた部品がつぶれて読めないため。
- **実在しない**ものだけを偽物にする。KanjiVG の 6,701 字だけでなく、Unicode の漢字すべての部品の組み合わせ（IDS）と照らし合わせる。
  - 例：「氵＋寺」は KanjiVG にないが、Unicode には「洔」がある。
  - IDS は [BabelStone IDS](https://babelstone.co.uk/CJK/IDS.TXT)（Andrew West、Unicode 16.0 の 97,680 字）を使う。ファイルの説明に「個人・商用を問わず、許可もクレジットもなしで使ってよい」とある。CHISE 由来の cjkvi-ids は GPLv2 なので使わない。
  - IDS のデータは偽物を作るときだけ使い、ゲームにもリポジトリにも入れない（ダウンロードしてスクリプトに渡す）。
  - 照らし合わせるときは、部品の異体字（每と毎など）をそろえ、部品をさらに細かく分けた形どうしでも比べる。IDS は「海 = ⿰氵每」、KanjiVG は「海 = 氵＋毎」のように、書き方が違うことがあるため。
- 1問の偽物3つは互いに重複しない。
- 次の漢字は出題しない：部品に分けられない漢字（一・山・木など）、部首がない漢字、部首以外の部分がない漢字、偽物を3つ作れない漢字。

*問題データ*（2026-10-27 作成）

- `Assets/TechC/KanjiQuiz/Data/RealKanji/` の `RealKanji_<漢字セット>.json`。`Tools/generate_real_kanji_fakes.py` で作る。手で編集しない。

| ファイル | 難易度 | 出題できる字数 | 出題しない字数 |
|---|---|---|---|
| `RealKanji_Elementary.json` | 簡単 | 737 | 289 |
| `RealKanji_JoyoCommon.json` | 常識 | 498 | 56 |
| `RealKanji_JoyoRare.json` | 困難 | 495 | 60 |
| `RealKanji_Hyogai.json` | （使わない。人名漢字のモード用） | 685 | 85 |

- 1字につき偽物の候補を最大 12 個入れる。ゲームでは、この中から毎回3つを選ぶ。
- 形式（1問を1行に書く）：

```json
{"kanji":"海","reading":"カイ","radical":"氵","position":"left","radicalGroups":["kvg:06d77-g1"],
 "fakes":[{"part":"舎","donor":"捨","groups":["kvg:06368-g2"],"reading":"シャ","box":[59.28,12.08,32.99,80.07]}, …]}
```

  - `radicalGroups`：本物の SVG で残す部首のグループの id。それ以外の画を、借りた部品に入れ替える。
  - `donor`・`groups`：部品を借りる漢字と、その SVG のグループの id。`groups` が空なら、`donor` の画をすべて使う（漢字1字をまるごと借りる）。
  - `part`：借りた部品の漢字（振り返りで「氵＋舎」のように出す）。`reading`：偽物の読み（`part` の音読み）。
  - `box`：借りた部品を置く枠（KanjiVG の座標で x, y, 幅, 高さ。y は下向き）。ゲームの `FakeKanjiComposer` は、借りた部品の外枠をこの枠に合わせる。

*使用例の熟語のデータ*（2026-10-27 作成）

- `Assets/TechC/KanjiQuiz/Data/KanjiWords/` の `KanjiWords_<漢字セット>.json`。`Tools/generate_kanji_words.py` で JMdict から作る。手で編集しない。
- 漢字セットの漢字すべてについて作る（本物の漢字さがしの振り返りのほか、漢字帳や書き順クイズの振り返りでも使える）。
- 形式（1字を1行に書く）：`{"kanji":"海","words":[{"word":"海外","reading":"かいがい"},{"word":"北海道","reading":"ほっかいどう"},{"word":"海上","reading":"かいじょう"}]}`
- 選び方：
  - 2〜4字の、漢字だけでできた言葉。ほかの漢字も、その漢字の難易度以下の漢字セットにあるもの（簡単なら小学漢字だけでできた言葉）。
  - JMdict でよく使われる印（`ke_pri`）のある言葉を、よく使われる順に3つまで。選んだ言葉を含む長い言葉（海外と海外旅行など）は選ばない。
  - 3つに満たなければ、1字で使う言葉（鞄（かばん）など）も使う。1つもなければ、印のない2字の言葉を2つまで。
  - 当て字・まれな書き方・まれな読み、下品・差別的・古い言葉は使わない。
  - JMdict に印がなくても子ども向けでない言葉（性・遊郭・薬物・賭博・反社会的な組織・むごい殺し方・自殺・ののしりなど）は、スクリプトの `EXCLUDED_WORDS` で外す（2026-11-01）。ニュースでふつうに使う言葉（殺人・強盗・賄賂など）は残す。淫・絞は熟語なしにする（`NO_UNCOMMON_FALLBACK`）。
- 熟語のない字：小学 0 字、常用（よく使う）2 字、常用（あまり使わない）6 字、常用外 98 字（本物の漢字さがしで出題する 1,730 字のうち 8 字）。振り返りでは熟語の欄を出さない。

*意味と例文のデータ*（2026-10-31 作成）

- `Assets/TechC/KanjiQuiz/Data/KanjiMeanings/` の `KanjiMeanings_<漢字セット>.json`（Elementary 737字・JoyoCommon 498字・JoyoRare 495字。出題する字すべて）。
- AI（Claude）で作り、`Tools/check_kanji_meanings.py` で確かめた。直すときは JSON を手で直し、このスクリプトで確かめ直す。
- 形式（1字を1行に書く）：`{"kanji":"海","meaning":"{地球|ちきゅう}の{上|うえ}に{広|ひろ}がる、しおからい{水|みず}のあつまり。","example":"{夏休|なつやす}みに{家族|かぞく}で海へ{泳|およ}ぎに{行|い}った。"}`
  - 意味と例文の中の漢字には `{漢字|よみ}` の形で読みをつける（出題する字だけは読みをつけない）。ゲームは `RubyText` で、漢字のまま、またはひらがなにして出す。
- 決まり（スクリプトで確かめる）：
  - 意味は15〜30字ほど、例文は20〜30字ほど（どちらも表示する文で40字以内）。例文には出題する字を入れる。
  - 使う漢字は、その字の難易度以下の漢字セットにあるものだけ（簡単なら小学漢字だけ）。々は使ってよい。
  - 読みはひらがなだけ。読みのない漢字を残さない。
- 意味の正しさ、例文の自然さ、読みの正しさはスクリプトでは確かめられないので、確認用の一覧（claude.ai のアーティファクト「意味と例文の確認」）で目で確かめる。

*作り方（実装の方針）*

- 偽物の候補は `Tools/` の Python で**事前に作り**、JSON にする。ゲームでは、その中から毎回3つを選ぶ。
  - JSON に入れるのは、本物の漢字、部品を借りる漢字、借りる部品の id、偽物の読み。座標はゲームで SVG から組み立てる。
  - JSON は `IQuestionRepository`（`LocalQuestionRepository`）経由で読む。
- 4つとも、書き順クイズと同じく KanjiVG の SVG の線（LineRenderer、`KanjiGlyphRenderer`）で、完成形だけを描く。本物だけフォントで出すと、見た目の違いで見抜けてしまうため。
  - 偽物は、本物の SVG の部首のグループの画に、部品を借りる漢字の SVG のグループの画を足して作る（`FakeKanjiComposer`）。借りた部品は、問題データの `box`（部品を置く枠）に合わせて、縦横それぞれの比率で縮める・伸ばす。
  - 偽物の候補から3つを選ぶとき、部品を借りる漢字の SVG がないなどで組み立てられないものは飛ばし、次の候補を使う。3つ作れなければ、その漢字は出題しない。
- 問題は `RealKanjiQuestion`（選択肢ごとの画のデータ、読み、説明、正解の番号）。進行と判定は `ChoiceQuizPresenter` を使う。

*画面*（`RealKanji.unity`。シーンのひな形から作った。共通の部品は 4章と同じ）

| オブジェクト | コンポーネント | 役割 |
|---|---|---|
| GameManager | RealKanjiEntryPoint | 問題を作り、Model・View・Presenter をつなぐ。難易度ごとの問題データ、熟語のデータ、選択肢の数（4）、モードの定義（Data/Modes/Mode_RealKanji）もここ |
| Canvas/ModeContent | ChoiceListView / RealKanjiView | 選択肢（RealKanjiChoice プレハブ）を Container に並べる。選択肢の字と読み、苦手の印、振り返りの読みと使用例を出す |
| ModeContent/QuestionText | TextMeshPro | 「本物の漢字はどれ？」。振り返りでは隠す。子の WeakMark は苦手な漢字のときに出す「苦手」のハンコ |
| ModeContent/Container | GridLayoutGroup | 選択肢を 2×2 に並べる（1つ 700×300） |
| ReviewPanel/AnswerInfoText | TextMeshPro | 振り返りで、問題文の場所に本物の読みと使用例を出す |
| DebugDifficultySwitcher | DebugDifficultySwitcher | テスト用の難易度切り替え（F1、書き順クイズと同じ） |

- 問題を切り替えるときは、問題文と選択肢（QuestionText、Container）がスライドする。
- **RealKanjiChoice プレハブ**（`Prefabs/Modes/RealKanji/`）：行のどこを押しても選べる選択肢（ChoiceItemView）。Content の下に RealKanjiChoiceContentView、Body（字の Glyph と読みの ReadingText）、振り返りの説明（DescriptionText）。字は 1辺 210px ほど。ふだんは字と読みを真ん中に置き、振り返りで説明を出すときだけ左へずらす。
- 偽物は KanjiVG から作ったものなので、KanjiVG のクレジットに含まれる。JMdict のクレジットも足す。BabelStone IDS はクレジット不要だが、お礼としてクレジット画面に載せる。

**人名用漢字の扱いと、人名漢字のモード**（2026-10-27 に決定）

- **人名用漢字は、ほかのモードに混ぜない**。どのモードも、出題範囲は常用漢字（2,136 字）の中で決める（5.2）。
  - 理由：名前に使う漢字は、人名用漢字に加えて異体字や旧字体まで含めると数がとても多く、「何でもあり」の状態になっている。クイズの答えとして「本物かどうか」「正しい書き順か」を問うには向かない、というアドバイスを受けた。
  - 以前の難易度「困難」（常用漢字以外の 770 字）は、644 字が人名用漢字で、残りも姓（趙・崔・姜）や異体字（煕・渕）など名前に使う字が多かった。
- 人名用漢字は、別に**人名漢字のモード**を作って扱う。遊び方・問題数・難易度を分けるかは未定（Progress.md 7章）。
- そのモードで使えるように、常用漢字以外の漢字セット `KanjiSet_Hyogai.json`（770 字）と、その偽物（`RealKanji_Hyogai.json`、685 字）・熟語（`KanjiWords_Hyogai.json`）のデータを残している。どの難易度にも使っていない。
  - `Hyogai` には、常用漢字の旧字体にあたる人名用漢字（顯・眞など）は入れていない。使うときは、モードの内容に合わせて範囲を決め直す。

**読み当て**（フェーズ1。2026-11-07 に決定し、同日に実装して Play で確認。実装は `Scripts/Modes/ReadingQuiz/`、シーン `ReadingQuiz.unity`、モード定義 `Mode_ReadingQuiz`）

- 熟語を見せ、正しい読みを選ぶ（選択式）。正しい読みが2つ以上ある問題（複数回答）もある。
- まちがいの候補は、同じ字を含む別の熟語の読みを先に使い、残りは読みの似た別の熟語の読みで埋める。
- 難易度は、熟語の一番難しい字の漢字セットと、読みの種類で分ける（2026-11-07 に決定。作り直し）：
  - 簡単＝小学漢字（Elementary）だけの熟語のうち、子どもが普段使う語として手作業で選んだもの（294語）。普通の読み
  - 常識＝大人が日常で読める普通の熟語（常用漢字を含むものと、簡単から移した語）。普通の読み。専門用語・固有名詞・古い語は外す（13,855語）
  - 困難＝普段は読まない読み（当て読み・難読語・古い読み・まれな読み。印のあるものを含めて集める）（697語）。子どもに不適切な語と、わかりにくい語は外した
  - 判断は `Tools/reading_quiz_review.tsv` に残す（外す語・外す読み・難易度の移動）。データを作り直しても、判断は消えない
  - 固有名詞（JMdict の印で判定）と、同じ字の繰り返し（一一・九九など）は、どの難易度にも入れない
- 問題数は他のモードと同じ（5・7・7 問）。選択肢の数は、正しい読みが1つのとき 簡単 3・常識 4・困難 4。正しい読みが複数のときは、それより 2 つ多くする（簡単 5・常識 6・困難 6）（2026-11-07）。
- 同じ字で読みが分かれる熟語（下手：へた・したて など）は、意味によって読みが変わるので、正解は人が1問ずつ確かめてから使う。
- データは JMdict から `Tools/generate_reading_quiz.py` で作る（2026-11-07）。
- 困難に入れる「小説で使われるような語」は、JMdict に情報がないため、データの元を別に決める（AI で一覧を作って人が確かめる案など）。未定（8.3）。
- 振り返りの意味と例文は、AI で作って追加する（2026-11-07）。
- モード名は実装前に決める（案：`ReadingQuiz`）。

**使い分け**（フェーズ1。2026-11-07 に決定。遊び方は 2026-11-14 に決定し、同日に実装して Play で確認。実装は `Scripts/Modes/KanjiUsage/`、シーン `KanjiUsage.unity`、モード定義 `Mode_KanjiUsage`、選択肢のプレハブ `Prefabs/Modes/KanjiUsage/KanjiUsageChoice`）

*遊び方*

- 文の空いたところに合う言葉を、同じ読みの言葉の候補から1つ選ぶ（選択式。正解は1つ）。
- 出す問題は2種類。
  - 同じ読みの熟語（同音異義語）：「問題の（かいとう）を書く」→ 回答・解答・解凍
  - 同じ訓読みの字（異字同訓）：「今日は（あつい）」→ 暑い・熱い・厚い。文化庁の「『異字同訓』の漢字の使い分け例」が参考になる
- 空いたところには、その言葉の読みを出す（送り仮名も含めた言葉全体の読み）。候補も送り仮名つきで出す。
- 文は、正しい使い方の文だけを作る（AI で作り、人が確かめる。意味と例文と同じ作り方）。
- 出題するのは、常用漢字だけでできた言葉。

*難易度*

字の範囲（ほかのモードと同じ）に、まぎらわしさを足して分ける。

| 難易度 | 出す組 | 問題数 | 選択肢 |
|---|---|---|---|
| 簡単 | 小学校で習う字だけの言葉で、意味がはっきり違う組（暑い・熱い、早い・速い） | 5 | 3 |
| 常識 | 常用漢字の言葉の組 | 7 | 4 |
| 困難 | 意味の近い組（保証・保障・補償、追求・追及・追究） | 7 | 4（よく使う言葉がちょうど3つの組は 3） |

*候補の作り方*

- 候補は、同じ読みの**実在する言葉だけ**にする。実在しない組み合わせ（「会答」など）は作らない（まちがった言葉を覚えさせないため）。
- 同じ読みの言葉が選択肢の数に足りない組は出さない。ただし困難の、意味の近い言葉がちょうど3つの組（保証・保障・補償、追求・追及・追究）は、定番の問題なので3択で出す（2026-11-14 に決定）。
- 選択肢の数は問題データのまちがいの数で決まる（ゲームは数に合わせて並べる）。
- 候補の一覧は `Tools/extract_kanji_usage_groups.py` で JMdict から取り出す（`Tools/kanji_usage_candidates.tsv`）。問題の元データ（文・まちがい・意味）は `Tools/kanji_usage_source.tsv` に AI が書き、`Tools/generate_kanji_usage.py` で確かめて `Data/KanjiUsage/` の JSON にする。
- 言葉の組の元は JMdict（同じ読みで、常用漢字だけの、よく使う言葉）。文と意味は AI で作り、人が確かめる。

*振り返り*

- 正解の言葉と文に加えて、候補それぞれの短い意味を並べ、違いが分かるようにする（例：回答＝問いや求めに答えること／解答＝問題を解いて答えること）。
- 漢字帳には、正解した言葉を言葉のまま集める（読み当てと同じ）。苦手な問題・自己ベストもほかのモードと同じ。

*画面と操作（実装）*

- 上に文（最大2行）、その下に案内、その下に選択肢を縦に並べる（1行に、数字キーの番号、チェック、言葉）。選択肢の数は3〜4つ。
- 空いたところは、橙色の「（かいとう）」と出す。選択肢は、押すか数字キーで選ぶ。選ぶと [次へ] が押せる。
- 苦手な言葉の問題には、文の右に「苦手」のハンコを出す（ほかのモードと同じ。1回のプレイに問題数の半分まで）。
- 中断メニューの「出題の字のほかは ひらがなで表示」を入れると、文の漢字がひらがなになる（選択肢の言葉は漢字のまま）。プレイ中・振り返りの途中に切り替えても、すぐ出し直す。
- 振り返りでは、空いたところに正解の言葉を緑の下線で入れた文を出し、選択肢の行ごとに意味を並べる。正解の行は緑、選んだまちがいの行は赤で、「正解」「あなたの回答」の印をつける。
- 問題の切り替えでスライドするのは、文と選択肢の一覧。

**文章クイズ**（旧・返信文クイズ。余裕があれば。2026-11-07 に名前と位置づけを変更）

- ある状況やメッセージが示され、それに合った返信の文を複数の候補から1つ選ぶ（選択式）。
- 候補には、漢字の誤りや言葉の使い方の誤りを含む文を混ぜる。
- 2026-10-27：正しい返信文を作る力がまだ足りないため後回しにした。
- 2026-11-07：正解が人によって変わりやすいため、作るなら「文の中で正しい漢字や言葉を選ぶ」形に寄せる（使い分けと近くなる）。余裕ができてから決める。

**四字熟語づくり**

2026-11-02 に遊び方を決めた（モックアップは claude.ai のアーティファクト「四字熟語づくりの遊び方案」の案 A）。

*遊び方*

- 四字熟語の**意味**（いつも表示）と、4つのマスを出す。いくつかのマスが空いていて、下に並んだ候補の字から選んで埋める。
  - 意味の中に空いたマスの字があると答えが見えてしまうので、プレイ中は、その字を含む言葉を読み（ひらがな）で出す（例：老若男女で「若」が空いていれば「お年寄りもわかい人も…」。`FourCharIdiomHint`）。振り返りと漢字帳では漢字のまま出す。
- 難易度で、空いているマスの数と候補の数を変える。難しくなるほど「つくる」感じが強くなる。

| 難易度 | 空いているマス | 候補の字 | 例（一石二鳥） |
|---|---|---|---|
| 簡単 | 1つ | 4つ（正解1＋まぎらわしい字3） | 一 石 二 □ ← 鳥・羽・頭・匹 |
| 常識 | 2つ | 6つ（正解2＋まぎらわしい字4） | 一 □ 二 □ ← 石・鳥・岩・羽・目・頭 |
| 困難 | 4つ（全部） | 12（正解4＋まぎらわしい字8） | □ □ □ □ ← 12 の字から並べる |

- 空けるマスは、問題を作るときにランダムに決める。候補の並びもランダム。
- 候補を押すと、左から数えて最初の空いたマスに入る。埋めたマスを押すと、その字は候補に戻る。空いたマスがなくなると [次へ] を押せる。
- 入れた4字が熟語と同じなら正解。同じ字が2回出る熟語（自問自答など）は、候補にその字を2つ置き、どちらを使っても正解にする。
- 回答した直後には正誤を出さない（ほかのモードと同じく、結果画面でまとめて出す）。結果画面の一覧では、○×を熟語の右に置く（`ResultItemView` が文字の長さに合わせてずらす）。[前へ] で戻ると、入れた字を元に戻す。
- 難易度は**知られている度合い**で分ける（字の難しさではない）。簡単＝子どもでも知っている（一石二鳥、十人十色）、常識＝大人ならたいてい知っている（臨機応変、試行錯誤）、困難＝あまり見かけない（合従連衡、呉越同舟）。熟語に使う字は常用漢字だけ（人名用漢字は使わない）。
- 問題数（5・7・7問）、級、自己ベスト、苦手な熟語の復習は、ほかのモードと同じ。保存のキーは `BestRecord_FourCharIdiom_<難易度>`・`WeakQuestions_FourCharIdiom_<難易度>`。
- 振り返りでは、正解の熟語と自分が入れた字、読み、意味、例文を出す。
- 漢字帳には、正解した四字熟語を**熟語のまま**登録し、意味を出す（2026-11-03 に決定・実装。例：虎視眈々を正解したら、虎視眈々が載る）。漢字帳の4つ目のタブ「四字熟語」に、問題データの全 240 語を簡単→常識→困難の順に並べ、正解した熟語だけを書きこむ（まだの熟語は「？？？？」）。キーは `KanjiBook_FourCharIdiom`。
  - 漢字帳の保存の形式を、集めたものを1つずつ改行で区切る形に変えた（それまでは字をつなげただけだったので、熟語が1字ずつに分かれてしまうため）。前の形式で保存した記録も読める（`PlayerPrefsKanjiBookRepository`）。
- 難易度の黒板では、出題範囲を「だれでも知っている熟語から 5問」のように出し、苦手な問題の見出しを「苦手な熟語」にする（モードの定義の `questionNoun`）。
- キー操作：候補は 1〜9・0・-・^（1〜12 番目）、Backspace（Delete）で最後に入れた字を戻す。Enter で次へ、← で前へ（ほかのモードと同じ）。

*まぎらわしい字*

- 熟語の4つの位置ごとに、まぎらわしい字を3つずつ用意する（AI が選ぶ）。形が似た字（鳥・烏）、読みが同じ字（機・期）、意味が近い字（舟・船）など。
- 簡単は空いたマスの位置の3字、常識は空いた2つの位置の6字から4字、困難は4つの位置の 12 字から8字を選ぶ。
- まぎらわしい字を入れても、別の四字熟語にならないようにする（スクリプトで確かめる）。

*問題データ*（2026-11-03 作成。簡単 60 語・常識 90 語・困難 90 語）

- `Assets/TechC/KanjiQuiz/Data/FourCharIdiom/` の `FourCharIdiom_<難易度>.json`。
- 熟語の候補は、JMdict の四字熟語の印（misc の yoji）がある言葉から `Tools/extract_four_char_idioms.py` で取り出す（常用漢字だけでできたもの 1,403 語）。そこから AI（Claude）が、ふつうの4字の言葉（相関関係など）と子ども向けでない言葉を外し、知られている度合いで難易度を分け、読み・意味・例文・まぎらわしい字をつける。意味と例文の書き方は、本物の漢字さがしの意味と例文と同じ（`{漢字|よみ}`）。
- `Tools/generate_four_char_idioms.py` が確かめてから JSON を書く。常識の熟語は、2字を入れ替えて別の四字熟語にならないもの、困難の熟語は、熟語の字とまぎらわしい字で別の四字熟語（並べ替えを含む）が作れないものだけにする（2マス・4マスを空けるので、正しく並べても不正解になるのを防ぐ）。このため、同工異曲・天長地久・無念無想・雲散霧消は外した（異曲同工・天地長久・無想無念・雲消霧散もあるため）。

**画像で名前当て**（余裕があれば。2026-11-07 に位置づけを変更）

- 画像を見て、その物の名称（漢字表記）を当てる。
- 2026-11-07：答えが熟字訓・難読語に限り、人物や実在するキャラクターの画像は使わない（ライセンスと肖像の問題を避けるため）。
- 例：タンポポの画像 →「蒲公英」
- 回答方法（選択式か入力式か）と、画像の入手方法は未定。

## 3. 書き順クイズモード

漢字の**正しい書き順**を当てるモード。
1問ごとに1つの漢字について、書き順を1画ずつ積み重ねて描いた図が複数並び、その中から正しい書き順のものを1つ選ぶ。

### 3.0 ゲームの流れ

```
ゲーム開始
  └─ 出題リストから問題を作る（作れない漢字は除外）
      └─ 出題（1問目）
          ├─ 選択肢を1つ選ぶ（トグル）
          ├─ [次へ] 押下 → 正誤を記録 → 次の問題へ
          ├─ [前へ] 押下 → 1つ前の問題へ（以前の選択を復元）
          └─ 最終問題で [次へ] → 結果画面へ
```

1. ゲーム開始時に、出題リストのすべての漢字について問題を作る。
2. 作った問題を、出題リストの順に出す。
3. プレイヤーは選択肢を1つ選び、[次へ] を押す。
   - 選択肢を選ぶと「コッ」、[次へ]・[前へ] を押すと紙をめくる音が鳴る。
   - 問題を切り替えると、問題文・漢字・選択肢がスライドして入ってくる（次へは右から、前へは左から、最初の問題は下から）。
   - 前に間違えた漢字（苦手な漢字、3.8）が出たときは、漢字の右に「苦手」のハンコを出す。
4. 何も選んでいない間は [次へ] を押せない。
5. 全問に回答すると結果画面（Result シーン）へ移る。
6. 結果画面では正解数と問題ごとの正誤（○・×）を表示し、[もう一度] で書き順クイズを最初からやり直せる。
   - 結果発表の演出：問題ごとの ○・× を1問ずつ効果音（正解・不正解）つきで出す → 正解数の数字をルーレットのように回す（回っている間はカチカチという音）→ 正解数を「ジャン」という音とともに出す → 級のハンコを押す → 全問正解なら花丸を書く → 自己ベストを出す → ボタンを出す。
   - ○ は朱色、× は青いハンコの画像で、押すように大きいところから縮んで出る。
   - 演出中に画面をクリックすると、残りを飛ばしてすぐに正解数・級・花丸・自己ベストを出す（ジャンの音だけ鳴らす）。
   - 演出中は [もう一度]・[問題を振り返る] を隠し、問題を押しても振り返らない。
   - 振り返りから結果画面に戻ったときは、演出をせずにすぐすべて表示する。
   - 演出の速さ（1問ごとの間隔、ルーレットの長さなど）は `ResultView` の Inspector で調整する。
7. 結果画面の [問題を振り返る] で、問題を振り返れる（3.5）。
8. 結果には級（3.6）と自己ベスト（3.7）を表示する。
9. プレイ中は右上の [メニュー] か Esc で中断メニューを開ける（4.4）。キーボードでも遊べる（4.5）。
10. シーンを切り替えるときは、前の画面がプリントのように上へ回収され、入れ替わりに次の画面のプリントが下から配られる（4.3）。

### 3.1 問題の表示

- 1問につき**選択肢3つ**（`StrokeOrderEntryPoint` の `choiceCount`、2〜4 で変更可）。
- 各選択肢は、書き順を1画ずつ積み上げた図を**横一列**に並べて表示する。
  - 例：5画の漢字なら「1画目まで」「2画目まで」…「5画目まで」の5つの図が並ぶ。
  - 1段階ずつの図を、漢字練習帳のマス目のように黒い四角で囲む。
- 図は1フレームに1段階ずつ描画され、アニメーションのように表示される。
- 選択肢のうち**1つだけ正解**で、正解の位置は問題を作るときにランダムに決まる。
- 残りの選択肢は、正解の書き順を難易度に応じて入れ替えた**不正解**になる。
- 不正解は、**正解とも、ほかの不正解とも重複しない**。
- 描画中に別の問題へ移ると、描画を途中で止める。

### 3.2 難易度

難易度はモード選択画面の黒板で選び、`QuizLaunchOptions.Difficulty` で受け取る。設定されていなければ Inspector の `StrokeOrderEntryPoint` の `difficulty` を使う（シーンを直接 Play したとき）。
テスト用に、F1 キーで画面左下に難易度の切り替えボタンを表示でき、押した難易度で最初からやり直せる（エディタと開発ビルドでだけ使える）。
難易度によって、出題範囲・問題数・不正解の作り方が変わる。

| 難易度（表示名） | 出題範囲 | 問題数 | 出題対象の画数 | 不正解の作り方 |
|---|---|---|---|---|
| Easy（簡単） | 小学漢字 | 5問 | 1画以上 | 全画をランダムに並べ替える |
| Normal（常識） | 小学校で学ばない常用漢字のうち、よく使う半分 | 7問 | 3画以上 | 連続した画数の30%（最低2画）を、すべて元の位置から動かす |
| Hard（困難） | 小学校で学ばない常用漢字のうち、あまり使わない半分 | 7問 | 5画以上 | 隣り合う2画を1か所だけ入れ替える |

- 「常識」で動かす画の数は、画数×0.3 を四捨五入した数（最低2画）。例：10画→3画、13画→4画、20画→6画。
- 「常識」「困難」は、違いが目立ちすぎないように、離れた画は入れ替えない。

- 出題範囲の詳細は 5.2 を参照。
- 出題する漢字は、出題範囲から毎回ランダムに選ぶ。同じプレイの中で同じ漢字は出ない。
- 画面上部のタイトルと結果画面には「書き順クイズ（簡単）」のように難易度を表示する。

次の漢字は問題を作らずに除外し、出題範囲から別の漢字を選び直す。

- 難易度の画数条件を満たさない漢字
- 重複しない不正解を必要な数だけ作れない漢字（選択肢3つの場合、1〜2画の漢字）
- 書き順データ（SVG）がない漢字

### 3.3 回答と採点

- 回答した直後には正解・不正解を表示しない。正誤は結果画面でまとめて表示する。

- 選択肢はトグルグループで管理し、同時に選べるのは1つだけ。
- チェックボックスだけでなく、行のどこ（書き順の図や余白）をクリックしても、その行を選べる。
- [次へ] を押した時点の選択で正誤を判定し、回答履歴に記録する。
- 回答履歴は問題ごとに「正解・不正解・未回答」の3状態を持つ。
- スコアは回答履歴のうち正解の数とする。

### 3.4 前の問題へ戻る

- [前へ] は1問目では押せない。
- [前へ] を押すと1つ前の問題を表示する。
- 戻った問題では、選択肢の並びは変わらず、以前の選択が復元される。
- 戻った問題で回答を変えて [次へ] を押すと、記録とスコアが上書きされる。

### 3.5 問題の振り返り

- 結果画面の [問題を振り返る] を押すと、最初に間違えた問題（全問正解なら1問目）から振り返りが開く。
- 結果画面の一覧で問題を押しても、その問題の振り返りが開く。
- 正解の行は緑の背景と「正解」、自分が選んだ不正解の行は赤の背景と「あなたの回答」で示す。自分の選択にはチェックが入る。
- 画面上部に「振り返り：正解／不正解」を表示する。
- 振り返りでは選択肢を押せない。[前へ]・[次へ] で問題を切り替え、[結果に戻る] で結果画面に戻る。
- 振り返りから結果画面に戻っても、結果はそのまま残る。[もう一度] を押すと通常の出題に戻る。
- 出題する漢字の右に、**お手本**として正しい書き順で1画ずつ筆で書くアニメーションを表示する（薄い字の上に、線が伸びていくように書く。書き終わったら少し待って繰り返す）。

### 3.6 級

正解率と難易度から「10級〜初段」の級を決め、結果画面でハンコとして押す（`KanjiRank`）。

| 難易度 | 全問正解 | 80% 以上 | 60% 以上 | 40% 以上 | 20% 以上 | 20% 未満 |
|---|---|---|---|---|---|---|
| 簡単 | 5級 | 6級 | 7級 | 8級 | 9級 | 10級 |
| 常識 | 3級 | 4級 | 5級 | 6級 | 7級 | 8級 |
| 困難 | 初段 | 1級 | 2級 | 3級 | 4級 | 5級 |

### 3.7 自己ベスト

- 難易度ごとに、最高の正解数を PlayerPrefs に保存する（キーは `BestRecord_StrokeOrder_Easy` など）。
- 前の記録を超えたら「自己ベスト更新！」を出して音を鳴らす。初めての記録は、1問以上正解していれば更新とする。
- 振り返りから結果画面に戻ったときは保存し直さず、更新の表示はそのまま残す。

### 3.8 苦手な漢字の復習

- 間違えた漢字を「苦手な漢字」として、難易度ごとに PlayerPrefs に保存する（キーは `WeakQuestions_StrokeOrder_Easy` など、改行区切り）。
- 正解した漢字は漢字帳に集める。モードごとに PlayerPrefs に保存する（キーは `KanjiBook_StrokeOrder`、漢字をつなげた文字列。難易度では分けない）。
- 次のプレイでは、苦手な漢字（その難易度の出題範囲にあるもの）を問題数の半分まで優先して出す（簡単は2問、常識・困難は3問）。残りは新しい漢字からランダムに選ぶ。出題順は混ぜる。
- 苦手な漢字に正解したらリストから外す。もう一度間違えたら一番新しくする。
- 覚えておくのは 30 字まで。超えたら古いものから外す。
- 振り返りでは「苦手」のハンコは出さない。

**BGM**（2026-11-24 に決定。コードは入れた。AudioSource・音源・中断メニューのつまみはまだ）

- ジャンルは、軽めのアコースティック系ローファイ（学校・勉強に合う穏やかなポップ）。歌詞やメロディの強い曲、激しいロックや EDM は避ける（考える邪魔になる）。和風は味付け程度にとどめる。
- 曲は**画面ごとに変えず、2曲だけ**（`BgmType`）：`Menu`（タイトル・モード選択・漢字帳。画面を移っても流しっぱなし）と `Quiz`（クイズ中と振り返り）。曲を切り替えるのは、モードを始めるときだけ。
- 結果画面は BGM を流さない（ルーレットと発表の効果音で見せるため）。クイズの曲をフェードアウトして止め、タイトルに戻ると `Menu` が再開する。
- 切り替え・停止はフェードアウトしてから行う（`AudioManager` の `bgmFadeSeconds`、初期値 0.6 秒）。クロスフェードはしない。残り時間の演出は、時間制限を作るときに考える。
- 鳴らすのは各シーンの EntryPoint（`IBgmPlayer.PlayBgm`・`StopBgm`）。`AudioManager` プレハブの `bgmSource`（AudioSource）と `bgmEntries`（曲・曲ごとの音量）をインスペクターで設定する。クリップがなければ警告を出して何も鳴らさない。
- 音量は PlayerPrefs（`Volume_Bgm`、初期値 0.5）に保存する。効果音より低くして、問題文や効果音をじゃましない。中断メニューのつまみは今後足す。
- 音源は、On-Jin の音源と同じ扱い：利用規約を確かめ、素材のまま取得できる状態になるものは `Art/Audio/External/` に置いて Git に入れない。音源を決めたら、取得の手順と利用の条件をここに書く。

### 4.3 シーンの切り替え

- `SceneLoader` に `SceneTransitionView` を渡すと、演出つきで切り替える（各 EntryPoint で渡している）。
- 前の画面をカメラで1枚描いてプリントにし、少し傾きながら上へ回収する（0.69 秒）。回収している間に次のシーンを読み込む。
- 回収が始まって 0.38 秒たったら（読み込みが遅ければ読み込み後に）、次の画面のプリントが下から少し傾いて配られ（0.69 秒）、机に落ち着くと影が消える（0.19 秒）。2枚の間から机が見える。
- 次の画面のプリントには次のシーンのカメラの映像をそのまま映すので、配られている間も画面は動いている。演出が終わると同じフレームでカメラを画面に戻す。
- プリントが動くたびに紙の音を鳴らす。
- 結果画面は、切り替えが終わってから結果発表を始める。
- カメラの映像に UI を入れるため、各シーンの Canvas は **Screen Space - Camera** にする（Overlay の UI はプリントに映らない）。
- 切り替えの途中はクリックを受け付けず、もう一度切り替えを頼まれても無視する。
- SceneTransition プレハブがないシーンでは、演出なしですぐに切り替える。

### 4.4 中断メニュー

- 見た目は机の上に開いた連絡帳（ScreenDesign.md 3.7 の S2）。左に「プレイを」（続ける・最初からやり直す・やめる）、右に「せってい」（効果音の音量・ひらがなで表示）。紙には罫線と赤い余白線、右下に先生の「確認」のハンコ。
- 右上の [メニュー] ボタンか Esc で開き、もう一度 Esc か [続ける] で閉じる。
- [最初からやり直す] で、今のシーンを読み込み直す（難易度はそのまま）。
- 効果音の音量をつまみで変えられる。すぐに反映し、PlayerPrefs（`Volume_Se`）に保存する。AudioManager が起動したときに読み込む。- 「出題の字のほかは ひらがなで表示」を切り替えられる。PlayerPrefs（`Option_Hiragana`）に保存し、最初は OFF。本物の漢字さがしの振り返りの意味と例文に効き、切り替えるとすぐ表示が変わる（`DisplaySettings`）。
- 開いている間は、後ろの画面のキー操作を止める（`InputGate`）。シーンの切り替えの途中は開かない。
- 書き順の線（LineRenderer）より手前に出すため、専用の Canvas（Screen Space - Camera、sortingOrder 20）に置く。カメラは `CanvasCameraBinder` が起動時に設定するので、プレハブを置くだけで使える。
- [やめる（時間割へ）] で、Title シーンを開いてモード選択（時間割）に戻る（`TitleLaunchOptions.OpenModeSelect`）。

|---|---|---|
| 1〜6（テンキーも可） | 選択肢を選ぶ。選択肢の行のチェックボックスの下に番号を出す | `ChoiceListView` |

### 4.6 シーンのひな形（新しいモードのシーンの作り方）

1. File > New Scene で「漢字クイズのモード」テンプレート（`Scenes/Templates/QuizScene.scenetemplate`）を選ぶ。
2. 共通の部品がそろったシーンができる：カメラ、EventSystem（決定・移動・キャンセルを外したもの）、AudioManager、SceneTransition、PauseMenu、Canvas（Screen Space - Camera）の下に Background・QuizFrame・ModeContent・ReviewPanel。
3. ModeContent の下にモードごとの UI を置き、GameManager にモードの EntryPoint を付ける。
4. QuizFrame の transitionTargets に、問題を切り替えるときにスライドさせるものを設定する。
5. `Data/Modes/` にモードの定義（Create > KanjiQuiz > モードの定義）を作り、`ModeCatalog` に加える。シーンを Build Profiles に登録する。

- 共通の部品はプレハブのままなので、プレハブを直せば全モードに反映される。
- テンプレートの元のシーンは `Scenes/Templates/QuizTemplate.unity`。共通の部品を増やしたら、こちらも直す。

## 5. 漢字データ

### 5.1 データソース

- [KanjiVG](https://kanjivg.tagaini.net/) の SVG ファイルを使用する。
- 配置場所：`Assets/StreamingAssets/KanjiVG/`（ビルド版でも読める）
- 基本の字形のファイル（6,701 ファイル）だけを置く。楷書体などの異体字のファイルは使わないので含めない。
- ファイル名：Unicode のコードポイントを5桁の小文字16進数にしたもの。
  - 例：「漢」(U+6F22) → `06f22.svg`
- ライセンス：Creative Commons 表示-継承 3.0（CC BY-SA 3.0）。
  - **リリース時にクレジット表記が必要。**

### 5.2 出題リスト

出題範囲は、難易度ごとの漢字セット（JSON）で決める。置き場所は `Assets/TechC/KanjiQuiz/Data/KanjiSets/`。

| ファイル | 難易度 | 内容 | 字数 |
|---|---|---|---|
| `KanjiSet_Elementary.json` | 簡単 | 小学校で学ぶ漢字（2020年度からの学年別漢字配当表） | 1,026 |
| `KanjiSet_JoyoCommon.json` | 常識 | 小学校では学ばない常用漢字のうち、新聞でよく使う半分（例：歳・企・援・施） | 554 |
| `KanjiSet_JoyoRare.json` | 困難 | 小学校では学ばない常用漢字のうち、あまり使わない半分（例：窟・箋・綻・遜） | 555 |
| `KanjiSet_Hyogai.json` | （使わない） | 常用漢字以外のうち、人名用漢字と、新聞での使用頻度の順位がある漢字 | 770 |

- 漢字セットは、漢字辞書データ [KANJIDIC2](https://www.edrdg.org/kanjidic/)（EDRDG、CC BY-SA 4.0）の学年情報と、新聞での使用頻度の順位（freq）から `Tools/generate_kanji_sets.py` で作る。
- 「常識」と「困難」は、小学校では学ばない常用漢字（1,109 字）を使用頻度の順位で並べ、前半と後半に分けたもの。順位のない漢字は「困難」に入れる。
- どの難易度も**常用漢字だけ**にする（2026-10-27 に決定）。以前は「困難」を常用漢字以外（`Hyogai`）にしていたが、770 字のうち 644 字が人名用漢字で、残りも姓（趙・崔）や異体字（煕・渕）など名前に使う字が多かった。人名に使う漢字は数がとても多く、何でもありになってしまうので、ほかのモードには混ぜない。
- `Hyogai` は、あとで作る人名漢字のモード（内容は未定）のために残している。偽物と熟語のデータ（`RealKanji_Hyogai.json`、`KanjiWords_Hyogai.json`）も作ってある。常用漢字の旧字体にあたる人名用漢字（例：顯・眞）は入れていない。
- どのセットも、KanjiVG に書き順データがある漢字だけを入れる。
- 「𠮟」（常用漢字）は、フォント（Klee One）に字形がなく出題する漢字を表示できないため、出題範囲から外している。
- JSON の形式：`{ "id": "Elementary", "title": "小学漢字", "source": "…", "kanji": "愛悪圧…" }`（kanji は漢字をつなげた1つの文字列）

### 5.3 書き順データの読み込み

1. 漢字からファイル名を作り、UnityWebRequest で SVG を読み込む。ファイルがなければその漢字を除外する。
2. `id` が `-s数字` で終わる `path` 要素を1画として、出現順に取り出す。この順番が正しい書き順になる。
3. 各画の `d` 属性（パスデータ）を解析し、座標の列に変換する。解析は問題を作るときに1回だけ行う。
   - 対応コマンド：M, L, H, V, C, S, Z（大文字・小文字とも）
   - 曲線（C, S）は1区間あたり30分割で近似する。
4. 座標は 109×109 の SVG 座標系を中心原点に変換し、3倍に拡大する。

## 6. 描画仕様

| 項目 | 既定値 | 設定場所 |
|---|---|---|
| 線の太さ | 0.15 | CumulativeStrokeRenderer |
| 線の色 | 黒 | CumulativeStrokeRenderer |
| 図と図の横の間隔 | 2.5 | CumulativeStrokeRenderer |
| 角・端の丸め頂点数 | 10 | CumulativeStrokeRenderer |
| 枠（1段階ごとの四角）の表示 | する | CumulativeStrokeRenderer の drawFrame |
| 枠の1辺の長さ | 3（KanjiVG の文字の範囲と同じ） | CumulativeStrokeRenderer の frameSize |
| 枠の線の太さ・色 | 0.4・黒 | CumulativeStrokeRenderer の frameWidth・frameColor |
| シェーダー | Sprites/Default | コード固定 |

- 1画は LineRenderer（KanjiLineRenderer プレハブ）1本で描く。
- 新しい問題を表示するときは、前の描画をすべて削除してから描き直す。
- 画数が多くて図を縮めるときは、画の線も同じ割合で細くする。枠の線はもともと細いので太さを変えない。
- 画は枠より手前に描く（画の描画順は枠より1つ大きい）。

### 8.2 既知の不具合

PR #1 のコードレビューで見つかった不具合は、書き順クイズの MVP 化ですべて解消した。

| 内容 | 対応 |
|---|---|
| SVG の読み込み先がエディタ専用のフォルダで、ビルド版では読めない | StreamingAssets へ移し、UnityWebRequest で読む |
| 不正解の選択肢が正解と同じ書き順になることがある | 重複しない不正解だけを作り、作れない漢字は除外する |
| 描画中に問題を切り替えると、前の漢字の図が混ざる | 問題を切り替えると描画をキャンセルする |
| SVG がない漢字を出題すると例外で止まる | その漢字を除外する |
| [前へ] で戻る先がスキップ対象だと元の問題に戻る | 問題は最初にまとめて作るので、スキップが起きない |
| 残りの問題がすべてスキップ対象だと前の問題が残る | 同上 |
| 前の問題に戻ったとき、以前の回答が表示されない | 以前の選択を復元する |
| SVG を Unity の SVG インポーターが読み込もうとして全件失敗する | StreamingAssets はインポートされないので解消 |

| 本物の漢字さがしの偽物で、部首と借りた部品が重なる（2026-10-27） | 部首の側から部品を置く枠を狭め、重ならない枠を JSON に入れる（詳しくは [BugFixes.md](BugFixes.md) 1章） |

| 本物の漢字さがしで、偽物が実在する字にそっくりに見えることがある（例：「胃」の偽物「月＋土」が「青」に見える。2026-11-01 にビルドの確認で発見） | 直さない（2026-11-01 にユーザーが判断） |

直した不具合の原因と直し方は [BugFixes.md](BugFixes.md) に書く。
