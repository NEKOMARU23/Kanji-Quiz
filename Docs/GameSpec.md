## 1. ゲーム概要

漢字をテーマにした**複数のクイズモード**で遊べるゲーム。
遊ぶだけでなく、プレイヤー自身が問題を作り、オンラインに公開して他のプレイヤーに遊んでもらうこともできる。

- ジャンル：教育・学習クイズ
- 想定プレイヤー：漢字を学習・確認したい人、問題を作って共有したい人
- 対象年齢：全年齢。子ども向けに限定はしないが、子どもも遊べるようにする
  - R18 などの不適切な内容に触れないようにする仕組みを用意する（2.4）

### 1.1 ゲームの柱

| 柱 | 内容 |
|---|---|
| 遊ぶ | 複数のゲームモードで漢字クイズを解く |
| 作る | 問題作成モードで、自分でクイズを作る |
| 共有する | 作った問題をオンラインに公開し、他のプレイヤーが作った問題を遊ぶ |

### 1.2 モード一覧

| モード | 概要 | 状況 |
|---|---|---|
| 書き順クイズ | 正しい書き順の図を選択肢から選ぶ | 実装中（3章） |
| 本物の漢字さがし | 偽物の漢字の中から、実在する漢字を当てる | 未着手（2.1） |
| 返信文クイズ | 状況に合った返信の文を考える | 未着手（2.1） |
| 四字熟語づくり | 漢字を組み合わせて四字熟語を作る | 未着手（2.1） |
| 画像で名前当て | 画像を見て、その名称を漢字で当てる | 未着手（2.1） |
| 問題作成モード | プレイヤーが問題を作る（2.3） | 後回し（フェーズ2） |
| オンライン問題 | 公開された問題を探して遊ぶ（2.4） | 後回し（フェーズ2） |

### 1.3 開発の優先順位

| フェーズ | 内容 | 時期 |
|---|---|---|
| フェーズ1 | ゲームモード5種を遊べる状態にする | 2027年1月の完成目標まで |
| フェーズ2 | 問題作成モード、オンライン共有、アカウント | フェーズ1の完了後 |

- フェーズ2を後から追加しやすいように、問題データはコードから分けて持つ設計にしておく。

## 2. 全体構成（構想）

> この章は今後の構想です。詳細は「8.3 決めること」で詰めます。

### 2.1 ゲームモード（構想）

書き順クイズ以外の4モードの概要。詳細は各モードの実装前に詰める。

**本物の漢字さがし**

- 実在する漢字1つと、それに似せた偽物の漢字を複数並べ、本物を選ぶ。
- 偽物の作り方（部首の入れ替え、画の追加や削除など）は未定。

**返信文クイズ**

- ある状況やメッセージが示され、それに合った返信の文を複数の候補から1つ選ぶ（選択式）。
- 候補には、漢字の誤りや言葉の使い方の誤りを含む文を混ぜる。

**四字熟語づくり**

- 提示された漢字を組み合わせて四字熟語を完成させる。
- 漢字の提示方法（ばらばらに並べる、一部を穴埋めにするなど）は未定。

**画像で名前当て**

- 画像を見て、その物の名称（漢字表記）を当てる。
- 例：タンポポの画像 →「蒲公英」
- 回答方法（選択式か入力式か）と、画像の入手方法は未定。

### 2.2 画面遷移（案）

```
タイトル
  └─ メニュー
      ├─ クイズで遊ぶ ─ モード選択 ─ 各クイズモード ─ 結果
      ├─ 問題を作る ─ 問題作成モード ─ 保存 / 公開
      └─ みんなの問題 ─ 問題一覧 ─ プレイ ─ 結果
```

### 2.3 問題作成モード（フェーズ2）

- プレイヤーが出題する漢字や問題形式を選び、問題を作る。
- 作った問題は端末に保存でき、オンラインに公開もできる。
- 作れる問題の形式は、基本的にゲームモードと同じにする。細部は要相談。

### 2.4 オンライン共有（フェーズ2）

- 作った問題をオンラインに公開できる。
- 他のプレイヤーは公開された問題を一覧から探して遊べる。
- サーバーはレンタルサーバーを借りて用意する。
- アカウントは作成できるようにするが、必須にはしない。ゲストでも遊べる。
- 不適切な内容（R18 など）に触れないようにする仕組みを用意する。
- 問題の探し方、評価、通報などの詳細は実装時に決める。

## 3. 書き順クイズモード

漢字の**正しい書き順**を当てるモード。
1問ごとに1つの漢字について、書き順を1画ずつ積み重ねて描いた図が複数並び、その中から正しい書き順のものを1つ選ぶ。

### 3.0 ゲームの流れ

```
ゲーム開始
  └─ 出題リストから問題を作る（作れない漢字は除外）
      └─ 出題（1問目）
          ├─ 選択肢を1つ選ぶ（トグル）
          ├─ [次へ] 押下 → 正誤を記録 → 次の問題へ
          ├─ [前へ] 押下 → 1つ前の問題へ（以前の選択を復元）
          └─ 最終問題で [次へ] → 終了画面を表示
```

1. ゲーム開始時に、出題リストのすべての漢字について問題を作る。
2. 作った問題を、出題リストの順に出す。
3. プレイヤーは選択肢を1つ選び、[次へ] を押す。
4. 何も選んでいない間は [次へ] を押せない。
5. 全問に回答すると終了画面（ConfirmationPanel）を表示する。結果画面ができるまでの仮の表示。

### 3.1 問題の表示

- 1問につき**選択肢3つ**（`StrokeOrderEntryPoint` の `choiceCount`、2〜4 で変更可）。
- 各選択肢は、書き順を1画ずつ積み上げた図を**横一列**に並べて表示する。
  - 例：5画の漢字なら「1画目まで」「2画目まで」…「5画目まで」の5つの図が並ぶ。
- 図は1フレームに1段階ずつ描画され、アニメーションのように表示される。
- 選択肢のうち**1つだけ正解**で、正解の位置は問題を作るときにランダムに決まる。
- 残りの選択肢は、正解の書き順を難易度に応じて入れ替えた**不正解**になる。
- 不正解は、**正解とも、ほかの不正解とも重複しない**。
- 描画中に別の問題へ移ると、描画を途中で止める。

### 3.2 難易度

難易度は Inspector の `StrokeOrderEntryPoint` の `difficulty` で設定する（現状はゲーム内で選択できない）。

| 難易度 | 出題対象 | 不正解の作り方 | 見分けやすさ |
|---|---|---|---|
| Easy | 1画以上の漢字 | 全画をランダムに並べ替える | 易しい |
| Normal | 3画以上の漢字 | ランダムに選んだ2〜3画だけを並べ替える | 普通 |
| Hard | 5画以上の漢字 | ランダムに選んだ2画だけを入れ替える | 難しい |

次の漢字は問題を作らずに除外する。

- 難易度の画数条件を満たさない漢字
- 重複しない不正解を必要な数だけ作れない漢字（選択肢3つの場合、1〜2画の漢字）
- 書き順データ（SVG）がない漢字

### 3.3 回答と採点

- 選択肢はトグルグループで管理し、同時に選べるのは1つだけ。
- [次へ] を押した時点の選択で正誤を判定し、回答履歴に記録する。
- 回答履歴は問題ごとに「正解・不正解・未回答」の3状態を持つ。
- スコアは回答履歴のうち正解の数とする。

### 3.4 前の問題へ戻る

- [前へ] は1問目では押せない。
- [前へ] を押すと1つ前の問題を表示する。
- 戻った問題では、選択肢の並びは変わらず、以前の選択が復元される。
- 戻った問題で回答を変えて [次へ] を押すと、記録とスコアが上書きされる。

## 5. 漢字データ

### 5.1 データソース

- [KanjiVG](https://kanjivg.tagaini.net/) の SVG ファイルを使用する。
- 配置場所：`Assets/StreamingAssets/KanjiVG/`（ビルド版でも読める）
- 基本の字形のファイル（6,701 ファイル）だけを置く。楷書体などの異体字のファイルは使わないので含めない。
- ファイル名：Unicode のコードポイントを5桁の小文字16進数にしたもの。
  - 例：「漢」(U+6F22) → `06f22.svg`
- ライセンス：Creative Commons 表示-継承 3.0（CC BY-SA 3.0）。
  - **リリース時にクレジット表記が必要。**

### 5.2 出題リスト

- `StrokeOrderEntryPoint` の `questionKanjiList` に漢字を1文字ずつ登録する。
- 現在の設定：「令」「漢」「字」

### 5.3 書き順データの読み込み

1. 漢字からファイル名を作り、UnityWebRequest で SVG を読み込む。ファイルがなければその漢字を除外する。
2. `id` が `-s数字` で終わる `path` 要素を1画として、出現順に取り出す。この順番が正しい書き順になる。
3. 各画の `d` 属性（パスデータ）を解析し、座標の列に変換する。解析は問題を作るときに1回だけ行う。
   - 対応コマンド：M, L, H, V, C, S, Z（大文字・小文字とも）
   - 曲線（C, S）は1区間あたり30分割で近似する。
4. 座標は 109×109 の SVG 座標系を中心原点に変換し、3倍に拡大する。

## 6. 描画仕様

| 項目 | 既定値 | 設定場所 |
|---|---|---|
| 線の太さ | 0.15 | CumulativeStrokeRenderer |
| 線の色 | 黒 | CumulativeStrokeRenderer |
| 図と図の横の間隔 | 2.5 | CumulativeStrokeRenderer |
| 角・端の丸め頂点数 | 10 | CumulativeStrokeRenderer |
| シェーダー | Sprites/Default | コード固定 |

- 1画は LineRenderer（KanjiLineRenderer プレハブ）1本で描く。
- 新しい問題を表示するときは、前の描画をすべて削除してから描き直す。

### 8.2 既知の不具合

PR #1 のコードレビューで見つかった不具合は、書き順クイズの MVP 化ですべて解消した。

| 内容 | 対応 |
|---|---|
| SVG の読み込み先がエディタ専用のフォルダで、ビルド版では読めない | StreamingAssets へ移し、UnityWebRequest で読む |
| 不正解の選択肢が正解と同じ書き順になることがある | 重複しない不正解だけを作り、作れない漢字は除外する |
| 描画中に問題を切り替えると、前の漢字の図が混ざる | 問題を切り替えると描画をキャンセルする |
| SVG がない漢字を出題すると例外で止まる | その漢字を除外する |
| [前へ] で戻る先がスキップ対象だと元の問題に戻る | 問題は最初にまとめて作るので、スキップが起きない |
| 残りの問題がすべてスキップ対象だと前の問題が残る | 同上 |
| 前の問題に戻ったとき、以前の回答が表示されない | 以前の選択を復元する |
| SVG を Unity の SVG インポーターが読み込もうとして全件失敗する | StreamingAssets はインポートされないので解消 |

現在わかっている不具合はない。

### 8.3 決めること

**ゲーム全体（フェーズ1）**

- 各ゲームモードの詳細ルール（2.1 の「未定」の項目）
- 各モードの問題データの作り方（偽物の漢字、四字熟語リスト、画像など）
- KanjiVG のクレジット表記の場所

**オンライン・問題作成（フェーズ2、実装時に検討）**

- 問題作成モードで作れる問題の形式の細部と、作成画面の操作
- ゲストとアカウントの違い（ゲストでも問題を公開できるか、など）
- 公開された問題の探し方（新着、人気順、検索、評価やいいね）
- 不適切な問題への対応（NGワード、通報、削除、公開前チェック）

**書き順クイズモード**

- 1回のプレイの問題数
- 制限時間の有無
- 正解・不正解時の演出（効果音、表示）
